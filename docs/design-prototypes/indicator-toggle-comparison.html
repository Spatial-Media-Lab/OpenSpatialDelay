Which Approach?

Both fix the visual issue — they differ in architecture

RECOMMENDED

A: New IndicatorToggle Component

Self-contained juce::Button subclass. Owns its own paint, mouse handling, and state. Each instance just needs: label text, accent color, optional APVTS binding.

Pros

  • Truly reusable drop-in
  • Self-sizing via getPreferredWidth()
  • Eliminates ~80 lines of duplicated paint code
  • No manual mouseDown/mouseMove
  • Built-in Button accessibility

Cons

  • More refactoring (5 instances)
  • Must handle APVTS + callback modes
MINIMAL

B: Convert FLT/MOD to TextButton

Make FLT/MOD actual TextButton instances, fix font to 10px, use measureToggle() for sizing. Keep paintStyledToggle() as shared renderer.

Pros

  • Smallest code change
  • Fixes visual issue immediately
  • Eliminates manual hit-testing

Cons

  • Paint logic still external
  • Empty-text TextButton is quirky
  • Harder to reuse elsewhere
