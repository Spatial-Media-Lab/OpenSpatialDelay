# v0.7 Feature Plan — "Per-Object DSP + ADM-OSC Send"

**Status:** Deferred — resume after code optimizations and UI/UX review
**Created:** 2026-03-13

---

## Feature 1: ADM-OSC Send (Completes Phase 4)

Transmit tap positions as ADM-OSC objects to external renderers (SPAT Revolution, L-ISA, Dolby Atmos Renderer).

- Add `juce::OSCSender` to PluginProcessor alongside existing `OSCReceiver`
- New parameters: `admOscSendEnabled` (bool toggle), non-APVTS: `oscSendIP` (string, default `"127.0.0.1"`), `oscSendPort` (int, default 4003)
- Send `/adm/obj/N/azim`, `/elev`, `/dist` per ADM-OSC spec
- 30 Hz send rate (every 2nd tick of existing 60Hz timer)
- Position-change gating: only send when position changes (>0.1° threshold)
- Extend OSC section in right panel: Send toggle + IP field + send port field
- Update `adm_osc_test.py` with a `--listen` mode to verify outgoing messages

## Feature 2: Per-Tap Filter Controls (Phase 5 — Creative DSP)

Individual HP/LP filter per delay object (Blackhole Immersive-style).

- New APVTS parameters (×12): `object{N}_filterLP` (20–20000 Hz, default 20000), `object{N}_filterHP` (20–20000 Hz, default 20)
- Per-object IIR filters (2nd-order Butterworth, same as existing feedback filters)
- Applied after pitch shift, before spatialization (new Stage 2.5)
- Coefficient update once per block, frequency-change gating (same pattern as feedback filters)
- Add LP and HP knobs to bottom panel per-object controls

## Feature 3: Per-Tap Pitch Shift Override (Phase 5 — Creative DSP)

Override global cumulative pitch with individual per-tap pitch control.

- New APVTS parameters (×12): `object{N}_pitchShift` (−24 to +24 semitones, default 0), `object{N}_pitchMode` (0=Cumulative, 1=Override)
- Cumulative mode (default): existing behavior (`k × globalPitch`), backwards compatible
- Override mode: tap applies its own `pitchShift` directly
- Feedback pitch always uses cumulative global (unchanged)
- Add PITCH knob + CUM/OVR toggle to bottom panel

## Bottom Panel Layout Concern

Adding 3 new controls (LP, HP, PITCH) to the bottom panel will exceed the current ~548px width. Recommended approach: **tabbed bottom panel**:
- **Tab 1 "Position":** ON/OFF, AZ, ELEV, DIST
- **Tab 2 "DSP":** LP, HP, PITCH (+ mode), DOP
- **Tab 3 "Motion":** TRAJ, SPEED

This keeps the window at 820×580px while accommodating all per-object controls.
