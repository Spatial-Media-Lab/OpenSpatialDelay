### IN-01: Dead code — `buildLegalNotices()` is defined but never called

**File:** `docs/generate_manual.js:1413`
**Issue:** The `...buildLegalNotices()` spread was removed from `mainContent`
(lines 1668-1689) during the legal-notices split, but the ~270-line
`buildLegalNotices()` function definition still lives at line 1413, preceded by
the banner comment `// SECTION 12: THIRD-PARTY NOTICES`. It is orphaned dead
code. Keeping it invites drift: future edits to the third-party table in this
function will silently have no effect, and a reviewer glancing at the file may
assume legal notices are still in the manual.

**Fix:** Delete the `buildLegalNotices()` function and its `// SECTION 12:
THIRD-PARTY NOTICES` banner from `generate_manual.js`. The canonical source of
this content now lives in `generate_legal_notices.js`.

### IN-02: Packager writes ZIP to repo root rather than `dist/` output dir

**File:** `scripts/package_macos_release.sh:21`
**Issue:** `ZIP_PATH="$REPO_ROOT/OpenSpatialDelay-$VERSION-macOS-arm64.zip"`
places the release artifact at the repo root. `.gitignore` correctly excludes
it via `OpenSpatialDelay-v*-macOS-*.zip`, but putting build outputs at the repo
root mixes generated artifacts with source files and is inconsistent with the
established `build/` and `dist/` staging convention.

**Fix:** Write the ZIP under `dist/` (or a sibling `release/` directory) so all
generated artifacts live under a single ignored path:

```bash
RELEASE_DIR="$REPO_ROOT/release"
mkdir -p "$RELEASE_DIR"
ZIP_PATH="$RELEASE_DIR/OpenSpatialDelay-$VERSION-macOS-arm64.zip"
```

If you keep the current location, document the output path in the script's
header comment so users know where to look.

### IN-03: VERSION argument is not validated for safe filename characters

**File:** `scripts/package_macos_release.sh:11-15`
**Issue:** `VERSION` is interpolated into a filename without format validation.
A typo like `bash scripts/package_macos_release.sh "v1.0 final"` or
`bash scripts/package_macos_release.sh /` produces a confusingly named ZIP
(`OpenSpatialDelay-v1.0 final-macOS-arm64.zip`) or writes to an unexpected
path. This is not an injection issue — quoting is correct — but it is a
usability guard worth adding on a release-critical script.

**Fix:** Validate against the semver pattern used elsewhere in the repo:

```bash
if [[ ! "$VERSION" =~ ^v[0-9]+\.[0-9]+\.[0-9]+$ ]]; then
  echo "ERROR: VERSION must match vX.Y.Z (got: '$VERSION')" >&2
  exit 2
fi
```

### IN-04: `find -maxdepth 4` may miss nested plugin bundles

**File:** `scripts/package_macos_release.sh:31`
**Issue:** The guard
`find "$DIST_DIR" -maxdepth 4 \( -name "*.vst3" -o -name "*.component" \)`
assumes the plugin bundle sits within four directory levels of `dist/`. If a
developer stages under `dist/macOS/Release/VST3/Foo.vst3` (five levels) the
guard will false-negative and abort with "No .vst3 or .component found" even
though the payload is staged correctly. Depth 4 is probably fine for the
current layout, but the limit is silent and easy to trip.

**Fix:** Remove `-maxdepth 4` (the search is fast and `dist/` is small), or
raise it explicitly with a comment justifying the ceiling:

```bash
# -maxdepth 6 covers dist/macOS/Release/VST3/Name.vst3/Contents/... layouts
if ! find "$DIST_DIR" -maxdepth 6 \( -name "*.vst3" -o -name "*.component" \) -print -quit | grep -q .; then
  echo "ERROR: No .vst3 or .component found under $DIST_DIR. Build the plugin first." >&2
  exit 1
fi
```

### IN-05: Inconsistent error recovery — DOCX is kept on PDF failure

**File:** `docs/generate_legal_notices.js:668-690`
**Issue:** `fs.writeFileSync(OUTPUT_PATH, buffer)` (line 668) writes the DOCX
before the `try { execFileSync(...) }` PDF step. If the PDF conversion throws
(soffice missing, conversion error, etc.), the script rethrows and exits
non-zero, but the stale DOCX remains on disk. A subsequent packaging run that
only checks for `OpenSpatialDelay_Legal_Notices.pdf` existence will fail as
expected, but a human skimming `docs/` sees a DOCX timestamped "now" and may
assume both artifacts are current. This is a mild
freshness/consistency footgun.

**Fix:** Either (a) delete the DOCX in the catch block before rethrowing, or
(b) write DOCX to a temp path first and only rename-to-final after the PDF
succeeds:

```js
try {
  execFileSync("soffice", [...], { stdio: "inherit" });
  console.log(`Wrote ${OUTPUT_PDF_PATH}`);
} catch (err) {
  try { fs.unlinkSync(OUTPUT_PATH); } catch (_) {}
  console.error("PDF conversion failed — DOCX also removed to keep artifacts in sync.");
  console.error("macOS install: brew install --cask libreoffice");
  throw err;
}
```

Low priority: the current behavior is obvious to the generator's author and
the two-artifact contract is enforced downstream by
`scripts/package_macos_release.sh` (which requires the PDF to exist).
