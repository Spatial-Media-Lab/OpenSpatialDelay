<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Tally iframe | Third-party script (`tally.so/widgets/embed.js`) loads in the user's browser and posts collected email + consent data to Tally's servers. Trust boundary: user input crosses from our static page into Tally's SaaS. |
| Build env → static HTML | `NEXT_PUBLIC_TALLY_FORM_ID` is inlined into the static HTML at build time. Public by design (NEXT_PUBLIC_ prefix) but still a boundary where a misconfiguration could expose an unintended form ID. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | I (Information Disclosure) | Tally embed iframe | mitigate | Use official Tally embed snippet verbatim (verified from tally.so/help/embed-your-form). Do NOT add analytics or intercept iframe events. The iframe is sandboxed by browser default — tally.so cannot read our parent page DOM. |
| T-02-04 | T (Tampering) | `NEXT_PUBLIC_TALLY_FORM_ID` inlined at build | mitigate | Use `NEXT_PUBLIC_` prefix (Next.js convention that makes this explicit). Placeholder card renders instead of a broken iframe if the env var is unset — fails safe. |
| T-02-05 | I (Information Disclosure) | Privacy page skeleton with `[Prose pending Plan 03.]` placeholders | mitigate | Page is not wired to DNS in this plan (Plan 03 cuts over DNS). If Netlify deploy preview URL leaks before Plan 03 prose lands, placeholders make it obvious the content is a draft. Plan 03 must replace every `[Prose pending Plan 03.]` before DNS cutover. |
| T-02-06 | S (Spoofing) | Script injection via `document.createElement('script')` with hardcoded tally.so URL | accept | The script URL is hardcoded to `https://tally.so/widgets/embed.js` (TLS, verified domain). No user-controlled input reaches the script src. Not a realistic spoofing vector for a static export. |
| T-02-07 | D (Denial of Service) | Tally iframe dependency | accept | If `tally.so` is down, the iframe fails to render and the user sees a blank area. Acceptable — there is no SLO on a Phase 2 pre-launch static site. `&lt;noscript&gt;` fallback links to tally.so directly for users who can still reach Tally. |

**No Content-Security-Policy (CSP) header in this plan** because static exports don't emit HTTP headers. CSP becomes Plan 03's responsibility (Netlify `_headers` file).
</threat_model>
