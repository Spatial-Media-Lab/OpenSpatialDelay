# Phase 2 — UI Design Contract

> Visual and interaction contract for the andrewrahman.com Next.js static shell
> (placeholder homepage + /privacy + /get-osd), the Tally email-gate form, and
> the Patreon page. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (Tailwind CSS 4 utility-first) |
| Icon library | none (no icons required for this phase's 2-page shell) |
| Font | system-ui stack (see Typography below) |

**Rationale (source: RESEARCH.md Standard Stack):** The andrewrahman.com shell
is a brand-new repo, currently non-existent. It delivers a 2-page static site
(homepage placeholder + /privacy) plus one embed page (/get-osd). shadcn adds
meaningful bootstrapping overhead for a scope this small and would impose a
component library on Phase 3 before that phase has made its own design
decisions. RESEARCH.md explicitly notes "no design-system overhead for a
2-page shell." Tailwind CSS 4 utility-first with no component library is the
correct fit. If Phase 3 introduces shadcn, it does so on its own terms.

**Registry safety gate:** Not applicable — no shadcn, no third-party component
registry.

## Typography

Use the system-ui font stack: `font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", system-ui, sans-serif`. No web font loading — keeps the site fast on a 2-page static shell and avoids self-hosting overhead for a placeholder phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.6 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading | 24px | 600 (semibold) | 1.2 |
| Display | 36px | 600 (semibold) | 1.1 |

**Rules:**
- Body (16px / 400 / 1.6) — all prose: homepage bio, privacy policy paragraphs, Tally form labels.
- Label (14px / 400 / 1.4) — form sublabels, footer attribution line, consent checkbox text.
- Heading (24px / 600 / 1.2) — page section headings (e.g. "Privacy Policy", privacy section headings like "What we collect").
- Display (36px / 600 / 1.1) — page title on homepage only (e.g. "Andrew Rahman"). One instance per page maximum.

**Exactly 2 weights:** 400 regular and 600 semibold. Do not introduce 500 or 700.

**Source:** Defaults. No upstream artifact specified typography. System-ui stack chosen to avoid Phase 2 web-font overhead on a placeholder page that Phase 3 will redesign anyway.

## Color

Dark-on-light minimal palette. Low-distraction: the homepage is a placeholder and the privacy page is a legal document. Neither should be visually loud.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, form background |
| Secondary (30%) | `#F5F5F5` | Footer background, subtle card/divider backgrounds |
| Text primary | `#111111` | All body and heading text |
| Text secondary | `#555555` | Labels, sublabels, footer attribution, consent checkbox text |
| Accent (10%) | `#1A1A1A` | Primary CTA button background, footer link hover underline |
| Link | `#0066CC` | Inline hyperlinks (privacy policy links, GitHub link, Patreon link, SML link) |
| Destructive | not used in this phase | n/a — no destructive actions in Phase 2 |

**Accent reserved for:** The single primary CTA button on each page only. Specifically:
- "Get OpenSpatialDelay" button on homepage
- Download buttons (macOS, Windows) on Tally thank-you screen

**Accent NOT used for:** Navigation items, section headings, decorative elements, or any element not listed above.

**Source (Claude's Discretion):** CONTEXT.md grants Claude full discretion over visual design within Tally's template constraints. Dark-on-light neutral palette chosen to:
1. Not commit Phase 3 to a brand color it hasn't chosen yet
2. Render the privacy policy as a clean legal document
3. Keep Tally form visually compatible (Tally's default theme is also light)

## Interaction Contracts

### /get-osd form embed

| State | Behavior |
|-------|----------|
| Initial | Tally form renders inside iframe. Email field empty, consent checkbox unchecked. Submit button disabled until both fields are filled and checkbox is checked. |
| Validation error | Tally native validation: email field shows inline error if format invalid. Consent checkbox shows inline error if unchecked on submit attempt. |
| Success | Tally's thank-you screen replaces the form (within the iframe). Thank-you heading + download buttons + soft Patreon CTA rendered. |
| Form unavailable | If Tally iframe fails to load, the Next.js page shows a fallback: "If the form doesn't load, visit [tally.so/r/{FORM_ID}](https://tally.so/r/{FORM_ID}) directly." |

### Download buttons (Tally thank-you screen)

| State | Behavior |
|-------|----------|
| Default | Two distinct buttons: "Download for macOS" and "Download for Windows". Each links directly to the v1.0.0 GitHub Release asset. Opens in new tab (target="_blank"). |
| Hover | Standard button hover (Tally's built-in style). No custom hover state needed — rendered by Tally, not custom code. |

### Navigation (andrewrahman.com)

| Element | Behavior |
|---------|----------|
| Nav slot | Empty minimal nav bar with site name "Andrew Rahman" linking to `/`. No additional nav items in Phase 2. Nav slot must exist in `<Layout>` for Phase 3 to fill. |
| Footer | Always-present: `/privacy` link + `github.com/Spatial-Media-Lab` attribution + copyright line. Footer renders on all pages via shared `<Layout>`. |

### Privacy policy page

| State | Behavior |
|-------|----------|
| Default | Long-form prose page. No interactive elements except inline hyperlinks. No accordion sections — policy must be fully readable without expanding sections (legal accessibility requirement). |
| Print / PDF | CSS print styles should preserve full text, hide nav/footer chrome if possible. Recommend `@media print { nav, footer { display: none; } }`. |

- Mobile breakpoint: 640px — reduce heading from 36px to 28px, maintain all other scales
